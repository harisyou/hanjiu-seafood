# Haris OS UX Principles

## One page, one responsibility

Each page should have one clear operational purpose. Secondary actions must not
compete with the primary task.

## Maximum three clicks

Frequent tasks should be reachable and completable with no more than three
meaningful clicks or taps whenever the workflow permits it.

## Large touch targets

Buttons, selectors, fields, and row actions must be comfortable to use on a
phone during active operations. Do not rely on hover or precise pointer input.

## Mobile-first

Design and verify the smallest screen first, then enhance layouts for larger
screens. Avoid wide tables and horizontal scrolling for routine tasks.

## Daily operations first

Prioritize product creation, price and availability updates, order review,
packing, and customer follow-up. Rare configuration tasks must not make daily
work slower.

## Fast over fancy

Prefer immediate feedback, readable information, and predictable controls over
animation or decorative complexity. Performance and clarity are part of the
user experience.

## Supporting rules

- Use consistent Traditional Chinese labels and status language.
- Show clear loading, empty, success, validation, and error states.
- Put the primary action where the operator naturally finishes the task.
- Confirm destructive or irreversible actions.
- Never expose exact inventory to customers; show a useful availability state.
- Preserve entered data when a recoverable error occurs.
