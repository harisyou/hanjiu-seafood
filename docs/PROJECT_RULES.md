# Haris OS Project Rules

These rules apply to every human and AI contributor.

1. Never push directly to `main`.
2. Use one feature or concern per branch.
3. Make small, focused commits with clear messages.
4. Design mobile first.
5. Deliver production-ready behavior, including errors and edge cases.
6. Never delete business data. Use statuses, availability, or archival states.
7. Keep UI language, components, spacing, and interaction patterns consistent.
8. Inspect existing code and workflows before changing them.
9. Extend existing architecture before proposing a rewrite.
10. Protect login, uploads, product management, cart, and order workflows from
    regressions.
11. Run lint when applicable and always run the production build before a Pull
    Request.
12. Document database migrations, environment changes, and deployment steps in
    the Pull Request.
